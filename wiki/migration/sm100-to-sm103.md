# Migrating Kernels from SM100 (B200) to SM103 (B300/GB300)

## Overview

SM103 is still Blackwell (tcgen05 / TMEM / TMA / CLC / NVFP4). Migration is **not** another Hopper→Blackwell rewrite. The failures teams hit are:

1. **Feature guards** that only accept `sm_100a`
2. **Schedules** tuned for B200 that leave Ultra NVFP4 peak on the table
3. **Backend heuristics** copied from SM100 (cuDNN vs CUTLASS, FA4 vs triton)
4. **Forward-compat cubins** (especially TRTLLM-gen attention) that hang on SM103
5. **Cluster math** wrong when 2-SM cooperative is enabled

## Migration Checklist

```
[ ] Add sm_103 / sm_103a to build matrix and CI
[ ] Replace sm_100a-only #ifdefs with SM100+SM103 family checks
[ ] Enable existing SM100 FP8/FP4 kernels on SM103 where binary-compatible
[ ] Add SM103 NVFP4 tile/cluster/scheduler specializations (keep SM100 configs)
[ ] Autotune per arch; do not hardcode SM100 winners
[ ] Prefer CUTLASS over cuDNN for FP4 GEMM on SM103 unless retuned
[ ] Raise epilogue store alignment to 256-bit where no-SMEM epilogue allows
[ ] Consider dedicated scale-factor TMA warp for Ultra blockscaled / grouped GEMM
[ ] Fix split-KV / CLC budgeting for 2-SM clusters
[ ] Gate TRTLLM-gen attention to exact CC 10.0 until vendor fix
[ ] Re-benchmark FA4, MLA cute-dsl, MoE DSL on real B300 hardware
```

## 1. Feature Guards and Quant Kernels

SM100a-only guards on `cvt ... e2m1x2` break on SM103a:

```cpp
// BEFORE (fails / skips on sm_103a)
#if defined(__CUDA_ARCH__) && (__CUDA_ARCH__ == 1000)
  asm volatile("cvt.rn.f16x2.e2m1x2 %0, %1;" : "=r"(out) : "r"(in));
#endif

// AFTER — include SM103a (pattern from pr-sglang-9807)
// Prefer CUTLASS arch macros or:
#if defined(__CUDA_ARCH__) && (__CUDA_ARCH__ >= 1000) && (__CUDA_ARCH__ < 1100)
  asm volatile("cvt.rn.f16x2.e2m1x2 %0, %1;" : "=r"(out) : "r"(in));
#endif
```

Also open SM100 FP8 entry points on SM103 rather than treating 10.3 as unsupported ([pr-sglang-9789](../../sources/prs/sglang/PR-9789.md)).

## 2. NVFP4 GEMM Schedules

Do **not** replace SM100 configs. Add SM103 candidates and autotune:

```python
# Conceptual dispatcher (FlashInfer-style)
def select_nvfp4_gemm_configs(cc_major, cc_minor):
    configs = list(SM100_NVFP4_CONFIGS)
    if (cc_major, cc_minor) == (10, 3):
        configs = configs + SM103_NVFP4_CONFIGS  # larger K, different clusters
    return configs
```

Observed SM103 wins are largest at higher batch sizes ([pr-flashinfer-2303](../../sources/prs/flashinfer/PR-2303.md)). Native SM103 paths use larger K tiles (e.g. CTA_K=768).

## 3. Epilogue: Store256 + Paired Scale

SM103 no-SMEM NVFP4 epilogues benefit from 256-bit output stores and `mul.f32x2` scale fusion ([pr-flashinfer-4063](../../sources/prs/flashinfer/PR-4063.md)):

```cpp
// Sketch — raise D alignment; fuse alpha*acc as f32x2
// Keep C alignment 128-bit if that is the ABI constraint.
template <class ElementD>
struct Sm103Nvf4Epilogue {
  static constexpr int kDAlignmentBits = 256;
  // device: mul.f32x2 on accumulator pairs when __CUDA_ARCH__ >= 1000
};
```

Reported geomean on B300: **~1.12×** autotuned, **~1.16×** fixed K768 tactic.

## 4. Backend Heuristics

```python
def pick_fp4_backend(cc):
    if cc == (10, 3):
        return "cutlass"   # CUTLASS > cuDNN on SM103 (pr-flashinfer-2404)
    if cc == (10, 0):
        return "cudnn"     # often still wins on SM100 with new cuDNN
    return "cutlass"

def pick_mla_backends(cc):
    # Always include cute-dsl on 10.3 — it is often fastest (pr-flashinfer-3888)
    return ["cute-dsl", "auto", "cutlass", "fa3"]  # illustrative
```

## 5. Grouped / MoE Blockscaled GEMM

Port SM100 grouped scheduling onto SM103 dense Ultra mainloop:

- Persistent group tile scheduler
- Per-group tensormap updates
- **Extra TMA warp for scale factors** (warp 6 in CUTLASS CuTeDSL SM103 example)

See [pr-cutlass-3124](../../sources/prs/cutlass/PR-3124.md).

## 6. 2-SM Split-KV Accounting

```python
# WRONG for 2-SM cluster MLA
max_splits = sm_count // batch

# RIGHT — each split occupies a cluster of cluster_ctas CTAs
max_splits = sm_count // (batch * cluster_ctas)  # cluster_ctas=2 for 2-SM
```

## 7. Forward-Compat Safety

```python
def supports_trtllm_attention(cc_major, cc_minor):
    # Exact SM100 only — SM103 hang under large batch
    # pr-vllm-38730, pr-sglang-21906
    return (cc_major, cc_minor) == (10, 0)
```

Symptom when wrong: infinite hang, ~99% SM util, ~0% memory bandwidth.

## 8. Toolchain Notes

| Issue | Fix |
|---|---|
| Triton `sm_103a` not defined | `TRITON_PTXAS_PATH=/usr/local/cuda/bin/ptxas` ([pr-vllm-30484](../../sources/prs/vllm/PR-30484.md)) |
| Wheels only ship sm_100 | Multi-arch gencode or SM103-specific JIT modules |
| FA4 unvalidated on B300 vision | Default triton attention on SM103 ([pr-sglang-25570](../../sources/prs/sglang/PR-25570.md)) |

## Expected Wins (order of magnitude)

| Change | Typical SM103 impact |
|---|---|
| SM103 NVFP4 schedules vs SM100 configs | up to ~10–15%+ on large-batch GEMM shapes |
| Store256 + f32x2 epilogue | ~12–16% geomean on native K768 path |
| CUTLASS vs cuDNN heuristic flip | shape-dependent; required for parity |
| Enable cute-dsl MLA on 10.3 | can be the fastest MLA backend |
| Fix 2-SM split oversubscription | removes wasted LSE reduction waves |
