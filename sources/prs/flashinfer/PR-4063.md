## Summary

Optimizes the native SM103 (`CTA_K=768`) CUTLASS NVFP4 GEMM epilogue on B300:

1. **Store256**: keep C/source alignment at 128-bit; raise D/output alignment to 256-bit so the no-SMEM SM103 epilogue can issue `STG.256` global stores.
2. **Paired scale**: local CUTLASS fusion callback evaluates `alpha * accumulator` with `mul.f32x2` on arch `>= SM100`, with scalar fallback for host/older paths.
3. Generic K128/K256/TMA-store paths unchanged.

## Performance (local B300 / SM103)

Geometric-mean speedup over prior epilogue across 14 production M/K/N shapes:

| Protocol | Store256 only | Store256 + `mul.f32x2` |
|---|---:|---:|
| Independently autotuned | 1.115× | 1.120× |
| Same native K768 tactic | 1.157× | 1.161× |

Codegen check on final library (63 tactics) shows large counts of `FMUL2` and direct `STG.256`.

## Kernel Relevance

Canonical evidence that SM103 NVFP4 kernels need **architecture-specific epilogue store width and scale fusion**, not only mainloop tile shapes. Complements earlier SM103 scheduler work (`pr-flashinfer-2303`).
